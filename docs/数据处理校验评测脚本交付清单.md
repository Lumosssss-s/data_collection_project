# 数据处理 / 校验 / 评测脚本交付清单（C3 · 施工图）

> **文档定位**：医疗数据流水线全部脚本的**交付清单**——数据加工（PDF→结构化）、入库（ES 路由）、校验（V1~V9）、评测（§9 指标）四族的逐脚本定义：输入 / 输出 / 依赖 / 运行方式 / 验收判据。
>
> **依据链**：数据形态与业务约束 ← 主方案 §5.3（流水线）/ §5.7.1~5.7.4（G1~G15 + 字段 + 词表 + V1~V9）/ §9（评测指标）；数据内容 ← 数据清单 19 类（10 项模板）；**索引归宿与 data_type 路由 ← C2《ES 索引与 Mapping 规范》**；代码改造落点 ↔ C1（BE-37/38 入库、BE-39~45 评测）。
>
> **边界声明**：只定义脚本契约，不含实现；硬口径承袭数据清单 §0.2——**纯文本（无 OCR）、仅癌症相关、无真实患者数据**。
>
> 版本：v1.0（2026-10-12 初稿 · 待检查点③确认）

## §1 P 族 · 数据加工流水线（6 个，全新）

> 总流水线（主方案 §5.3）：`PDF → 章节树 → LLM 抽取 → 人工抽检 → 校验(V) → 入库(I)`。P 脚本只负责前三步；人工抽检与签字（G15 / review_status）不脚本化，由数据清单 §1.4 角色分工承接。

### P-01 `pdf_extract.py` —— 指南 PDF → 结构化章节树

| 项 | 契约 |
|---|---|
| 输入 | `data/raw/<癌种>/` 下的原生 PDF/DOCX（**文本可提取**；扫描件直接报错退出，硬口径 1） |
| 输出 | `data/intermediate/<doc_id>_tree.json`：`{doc_id, title, toc[], sections:[{sec_path(breadcrumb), level, text, page}], doc_hash, extract_meta}` |
| 依赖 | PyMuPDF（PDF）/ python-docx（DOCX）；**需增补 requirements.txt 并重建镜像**（见 §7.3） |
| 要点 | ① breadcrumb 保留完整层级路径（`第三部分/3.2 早期治疗`，REC 溯源依赖）；② 每段带 page（REC.page 来源）；③ doc_hash = 原文件 SHA-256；④ 失败章节记 `extract_meta.warnings[]` 不中断 |
| 验收 | 3 份肺癌指南跑通；抽样 10 段文本与原文逐字一致；toc 与文档目录页吻合 |

### P-02 `rec_extract.py` —— 章节树 → 推荐条目 REC（LLM）

| 项 | 契约 |
|---|---|
| 输入 | P-01 输出的章节树 JSON |
| 输出 | `data/clean/recommendations/<文件>.json`（G2/G4 命名），字段 §5.7.2-2 全量 |
| 依赖 | DeepSeek API（JSON 模式）；内置**证据等级映射表**（原文表述 → high/moderate/low/very_low，原文另存 evidence_level_original） |
| 要点 | ① LLM 输出 JSON Schema 约束（失败重试 ≤2 次，仍失败记入失败清单不阻塞）；② verbatim 标记（原文摘录 true）；③ 一条 REC ≤500 字；④ 断点续跑（已抽 doc_id 跳过）；⑤ 抽完后自动触发 V-01 |
| 验收 | 肺癌 ≥400 条产出；随机抽 20 条人工比对准确率 ≥90%（才可进入抽检签字流程） |

### P-03 `profile_extract.py` —— 疾病档案 DIS（LLM 两遍）

| 项 | 契约 |
|---|---|
| 输入 | P-01 章节树（按疾病聚合）+ A5 术语字典（canonical 约束）+ CMeKG/DiseaseKG 关系子图 |
| 输出 | `data/clean/disease_profiles/<文件>.json`：14 section 专业版 + patient_version 患者版 |
| 依赖 | DeepSeek API；两遍调用：第一遍抽 14 section，第二遍按术语表约束生成患者版通俗改写（句均 ≤40 字） |
| 要点 | ① section 缺失填 null + section_gaps 说明（§5.7.2-3）；② links 实体一律 canonical 名（G9）；③ 症状条目 `{name, type, frequency}` 三键齐全；④ 患者版独立缓存，失败可单疾病重跑 |
| 验收 | 肺癌相关 ≥20 个 profile；每病抽 ≥3 个 section 双版本比对（§5.7.4 人工抽检） |

### P-04 `drug_struct.py` —— NMPA 说明书 → DRUG JSON

| 项 | 契约 |
|---|---|
| 输入 | `data/raw/` 说明书文本（NMPA 公开页面复制 / 文本 PDF） |
| 输出 | `data/clean/drug_labels/<文件>.json`（§5.7.2-4 字段） |
| 依赖 | LLM 辅助结构化（模板化段落：适应证/用法/禁忌/不良反应五段式，规则切分优先、LLM 兜底） |
| 要点 | ① 不良反应拆 `{term, frequency, ctcae_hint}`；② atc_code / approval_no 人工核对（LLM 不得编造，缺失置 null 待补）；③ adverse_reaction_terms 抽平字段同步生成（C2 §3.3） |
| 验收 | 30 份说明书结构化；五段式字段抽取人工抽检准确率 ≥90% |

### P-05 `term_build.py` —— 术语字典 TERM 构建

| 项 | 契约 |
|---|---|
| 输入 | ICD-10 / ICD-O-3 / ATC 码表 + 人工同义词编集表（5 癌种疾病名 / 药品通用名 / 检查 / 症状 / 基因 / 分期） |
| 输出 | `data/clean/terminology/<文件>.json`（§5.7.2-5 字段） |
| 依赖 | pypinyin（首字母拼音生成）；码表人工整理部分不走脚本 |
| 要点 | ① canonical 全局唯一性检查（重名直接报错）；② "肺CA/NSCLC/非小细胞肺癌"等别名进 synonyms；③ mapping_status 默认 pending，人工确认后置 confirmed；④ **此脚本产出是 BE-21 实体消歧与 G9 全局约束的地基，优先级最高** |
| 验收 | ≥2000 条起步版（批次一至少肺癌域完备）；六类各有覆盖；编码格式正则全过 |

### P-06 `kg_build.py` —— 图谱三元组 KG 构建

| 项 | 契约 |
|---|---|
| 输入 | REC/DIS 成品 JSON + CMeKG / DiseaseKG **癌症相关子图**（人工筛选后的关系表） |
| 输出 | `data/clean/kg_triples/<文件>.json`（§5.7.2-6：head/tail 为 canonical、九类 relation、evidence、confidence） |
| 依赖 | 无 LLM 必需（规则拼接为主）；子图对齐阶段人工参与 |
| 要点 | ① **只做静态数据交付**——线上运行时抽取（指纹缓存 + 幂等 upsert）由 BE-20 改造承接，两者共用 relation 九类枚举；② 开源子图关系逐条标 evidence 来源；③ DiseaseKG 来源数据标注"爬取，谨慎使用"（主方案 §5.5 合规注） |
| 验收 | 肺癌子图 ≥500 三元组；head/tail 100% 可在术语字典解析（V5 联动） |

## §2 V 族 · 校验脚本（2 个，全新）

### V-01 `validate_data.py` —— V1~V9 全项自动校验（入库闸门）

| 项 | 契约 |
|---|---|
| 输入 | `data/clean/<类型目录>/` 全部 JSON + 类型参数（或 manifest 指定文件集） |
| 输出 | `data/reports/validation_<时间戳>.json`：逐项 {检查项, 通过数, 失败清单（记录 ID + 字段 + 原因）}；**exit code ≠0 即失败**（CI / 入库前置条件可依赖） |
| 校验项 | 与主方案 §5.7.4 一一对应：V1 JSON Schema（每类型一个 schema 文件，随脚本维护）；V2 必填完整率；V3 ID 正则与唯一性（G5）；V4 枚举合法性（§5.7.3 词表内置于脚本常量，**与 BE-04 domain_enums 同源**）；V5 引用完整性（REC.doc_id→DOC、实体名→TERM、TPL.patient_messages→MSG；悬空输出清单）；V6 溯源五要素（G6）；V7 格式（UTF-8 无 BOM / 日期 YYYY-MM-DD / 无占位符空值 G8 / 数值单位拆分 G11 / 无全角混入 G10）；V8 脱敏正则扫描（G13）；V9 主键唯一 + 相似度 >0.95 重复对清单 |
| 位置 | **入库硬闸门：I-01 调用本脚本（--precheck 模式），不通过拒绝灌入** |
| 验收 | 用 3 组构造的坏数据（缺字段 / 非法枚举 / 悬空引用）验证全部拦截；好数据零误报 |

### V-02 `check_manifest.py` —— 交付清单与哈希复算

| 项 | 契约 |
|---|---|
| 输入 | 批次交付目录 + `manifest.json` |
| 输出 | 复算报告：文件清单一致性、记录数、SHA-256 逐文件复算、review_status=approved 占比 |
| 要点 | 对齐数据清单 §1.3 批次原则：每批必附 manifest；重交付版本 +1 不覆盖（G4）；**approved 占比 100% 才放行入库**（G15） |
| 验收 | 篡改一个字节能检出；缺 manifest 报错 |

## §6 运行方式与工程约定

### 6.1 运行位置

| 族 | 方式 | 说明 |
|---|---|---|
| P / V / I | `docker exec medical-backend python <脚本>`（源码挂载 `./medical_rag:/app`）或宿主 venv 直跑 | LLM 调用族（P-02/03/04、I-02）走容器内 env（MEDICAL_LLM_*）；纯本地族（P-01/05、V、P-06）宿主可跑 |
| E | 同上（`eval_data/` 内） | 现状 7 脚本均为 `main()` 直跑、无 argparse，医疗版改造时**统一补 argparse**（评测集路径 / 索引名 / 输出目录可传参），否则硬编码路径在容器内外不一致 |

### 6.2 工程约定（全族通用）

1. **幂等**：I-01 按 ES `_id` upsert；P-02/03 断点续跑（已处理 doc_id / disease_id 跳过）；V 族可重复运行；
2. **限流**：LLM 调用统一 delay ≥1s + 失败重试 ≤2 次（沿用 I-02 现状 delay=2.0 口径）；
3. **报告落盘**：P/V/I/E 全部输出结构化报告至 `data/reports/`（V 族）与 `eval_data/results/`（E 族），供验收与 P5 评测材料引用；
4. **日志**：stdout 进度（处理数 / 成功 / 失败 / 跳过四计数）+ 失败明细入报告，不静默吞错。
